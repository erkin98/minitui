'@minitui/catalog': minor

The validation gate is total over what a model can send: a malformed spec, element or binding is refused instead of throwing or being accepted silently, and so are values that are not plain JSON trees (cycles, nesting past 256, more than 65,536 nodes, reserved keys), keys the sanitiser would change, any `watch`, a binding key besides `action` and `params`, params that fail the action schema or omit a required key, `$path` and mistyped or empty-pointer markers, and a numeric size, padding, margin or gap above 1,000. Catalog definitions are refused when props or params are not a top-level `z.object`, when a schema is a refined object, when a permission descriptor is malformed or when a template hole has no leading slash. Issue text is sanitised and cut. The prompt is JSONL only and prints params, events and the state paths of gated actions, and `buildCatalogPrompt` throws when the generator's marker lines are missing. New exports: `MAX_ELEMENT_DEPTH`, `checkElementTree`, `hasCanonicalKeys` and the type `ElementTreeIssue`. Template holes are read from the template itself, so validation cost no longer grows with state size and state text holding `${/…}` is no longer reported as an unresolved binding. A gated action can name the state paths its progress and outcome are written to (`statusPointers`); the prompt prints them and the gate requires them in the generated state. A parameter named by a template hole must be bound to its own state root, and the summary template's holes are checked too. A saved spec that carries `watch`, a binding key other than `action` and `params`, or a key the sanitiser would change stops validating. The package now declares its licence, Apache-2.0.
